# Whitelists — инструмент проверки российских сервисов в режиме «белых списков»

Во время ограничений мобильные операторы включают режим «белого списка»:
трафик пропускается только к разрешённым ресурсам, остальное не работает.
Набор разрешённых ресурсов у каждого оператора свой и меняется во времени.

Этот проект отвечает на практический вопрос: **какие домены в вашей сети
сейчас реально работают**, — и собирает из ответа списки, по которым можно
пускать такие сервисы напрямую, минуя туннель.

Проект не публикует «правильные» списки: результат зависит от оператора,
региона и момента времени. Он даёт инструмент, чтобы снять свой замер
и получить свои списки.

> Почему замер устроен именно так, что показали замеры и какие ловушки
> встретились — в файле [OBSERVATIONS.md](OBSERVATIONS.md).

## Что вы получаете

После серии замеров в `release/` появляются списки:

| Файл | Что внутри |
| --- | --- |
| `whitelist-common.txt` | **один список для всех**: домен, который работает у каждого оператора, по которому есть замеры |
| `IP-whitelist-common.txt` | адреса этих доменов |
| `whitelist-<оператор>.txt` | домены, работающие у конкретного оператора (шире общего) |
| `IP-whitelist-<оператор>.txt` | адреса для этого оператора |
| `whitelist-common.meta.json` | дата сборки, список операторов и счётчики |

В репозитории лежат списки из нашего замера (МегаФон и Ростелеком):
это снимок на дату из `whitelist-common.meta.json`, и в вашей сети он может
отличаться — набор разрешённых ресурсов у оператора меняется. Берите его как
отправную точку и ориентир, а рабочий список соберите своим замером.

## Как это работает

Единица измерения — не домен, а пара **домен + адрес**: у домена бывает
несколько адресов, и часть может быть разрешена, а часть нет.

1. **Проверка пар** — по каждому адресу домена поднимается TCP и TLS
   с именем домена в SNI. Результат: `PASS`, `DROP` (SYN не дошёл), `RST`,
   `REFUSED`, `TLS_ERR`, `DNS_NX`.
2. **HTTP-проверка** — второе мнение: сервис должен отдать настоящий ответ.
   Отличает рабочую страницу от заглушки оператора, парковки и подмены
   сертификата.
3. **DNS-проба** — отвечает ли DNS оператора на имя (фильтр может быть
   и по именам).
4. **Вердикт** — `classify.py` собирает всё это по нескольким прогонам
   и решает судьбу домена: `разрешён`, `частично`, `не разрешён`,
   `нестабильно`.
5. **Сборка** — `build_common.py` оставляет в общем списке только то, что
   подтверждено у всех операторов.

## Требования

- Python 3.9 или новее.
- Любое устройство с доступом в интернет через оператора: телефон в режиме
  модема, USB-модем, роутер с модемом.
- На Linux дополнительно нужен `ip` (пакет iproute2) — он определяет канал.

Зависимости — в `requirements.txt` (нижние границы версий):

```bash
pip install -r requirements.txt
```

Без `curl_cffi` работает медленнее и хуже маскируется под браузер,
без `cryptography` не разбирается сертификат, без `dnspython` остаётся
системный резолвер.

## Установка на Linux

```bash
git clone https://github.com/kirilllavrov/whitelists.git
cd whitelists
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## Установка на Windows

```powershell
git clone https://github.com/kirilllavrov/whitelists.git
cd whitelists
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Если PowerShell запрещает активацию окружения, выполните от администратора:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

**Привязка к модему на Windows.** Работает так же, как в Linux, только
другим способом: вместо `SO_BINDTODEVICE` используется адрес адаптера
(в Windows пакет с таким адресом источника уходит только через свой
интерфейс). Модем можно не делать маршрутом по умолчанию:

```powershell
python tools/check.py -o Megafon --phase on --interface "Ethernet 3"
```

Имя адаптера показывает `Get-NetAdapter`, оно же печатается в отчёте.
Мобильный канал определяется по описанию адаптера («Remote NDIS based
Internet Sharing Device», «Apple Mobile Device Ethernet», WWAN), поэтому
раздача с телефона не считается домашней сетью.

Если интерфейс не указан, пробы идут по маршруту по умолчанию, и модем
должен быть им — как и раньше.

**`python` вместо `python3`.** В окружении Windows файла `python3.exe` нет:
после активации venv `python3` подхватит алиас Microsoft Store или системный
Python без зависимостей. В примерах ниже для Windows используйте `python`.

## Быстрый старт

Режим белого списка включён, модем подключён, Wi-Fi выключен:

```bash
# 1. свежие адреса доменов (делать до включения режима — потом DNS может не отвечать).
#    --local пишет в configs/dns-cache.local.json, не трогая общий кэш из репозитория
python3 tools/cache_dns.py --local --merge

# 2. один прогон: пары, HTTP-проверка, наблюдения в runs/, release
python3 tools/check.py -o Megafon --phase on

# 3. вердикты и списки
python3 tools/classify.py -o Megafon --phase on --write-release
```

Для общего списка по всем операторам, по которым уже есть замеры:

```bash
python3 tools/build_common.py --write-release
```

## Полный цикл

Один прогон недостоверен: фильтрация меняется в пределах минут. Для вердикта
нужна серия — минимум три прогона.

```bash
# базовая фаза (режим выключен) — нужна, чтобы отличать «нет в списке» от «сломан всегда»
for i in 1 2 3; do
    python3 tools/check.py -o Megafon --phase off --no-release
    sleep 180
done

# целевая фаза (режим включён) — из неё собирается release
for i in 1 2 3; do
    python3 tools/check.py -o Megafon --phase on
    sleep 180
done

# вердикты и списки
python3 tools/classify.py -o Megafon --phase on --write-release

# общий список по всем операторам с замерами
python3 tools/build_common.py --write-release
```

То же для PowerShell (`python`, не `python3`):

```powershell
1..3 | ForEach-Object {
    python tools/check.py -o Megafon --phase off --no-release
    Start-Sleep -Seconds 180
}
1..3 | ForEach-Object {
    python tools/check.py -o Megafon --phase on
    Start-Sleep -Seconds 180
}
python tools/classify.py -o Megafon --phase on --write-release
python tools/build_common.py --write-release
```

Переменные окружения вместо флагов — тоже по-разному:

```bash
LIMIT=50 python3 tools/check.py          # bash
```
```powershell
$env:LIMIT = 50; python tools/check.py   # PowerShell
```

> **Сколько это занимает.** Один прогон по 560 доменам — 40–60 минут: темп
> специально низкий, иначе в сети срабатывает шейпер и начинают теряться
> соединения, а замер врёт.

Флаг `--phase` обязателен по смыслу: `off` — «как работает сеть без
ограничений», `on` — «что разрешает оператор». Наблюдения раскладываются
по папкам `runs/<оператор>/<фаза>/`, release собирается только из `on`.

> **Прерывание.** Ctrl+C не теряет прогон: дочерний шаг дописывает уже
> собранное, наблюдения сохраняются с пометкой `interrupted`, HTTP-проверка
> и release не запускаются. Второй Ctrl+C бросает шаг сразу.

## Что на выходе

```text
runs/<оператор>/<фаза>/<дата>-pairs.jsonl    сырые пробы (в git не попадают)
runs/<оператор>/<фаза>/<дата>-pairs.tsv      только прошедшие пары
runs/<оператор>/<фаза>/<дата>-tls.txt        домены с прошедшими парами
runs/<оператор>/<фаза>/<дата>-http.txt       домены с подтверждённым содержимым
runs/<оператор>/<фаза>/<дата>-summary.json   сводка прогона

build/run-<дата>-<фаза>/                     журнал и отчёты одного прогона
build/classify/<оператор>-<фаза>/            вердикты: classify.json, report.md, *.txt
build/common/                                общий список: report.md, verdicts.json

release/                                     итоговые списки
```

Разбор вердиктов в `build/classify/<оператор>-<фаза>/`:

| Файл | Что внутри |
| --- | --- |
| `allowed.txt` | разрешённые домены |
| `partial.txt` | проходит не каждый адрес домена |
| `content-unconfirmed.txt` | адреса проходят, но сервис отдаёт заглушку или чужой сертификат |
| `blocked.txt` | не прошёл ни разу |
| `unstable.txt` | проходит реже порога — нужен ещё прогон |
| `ips-allowed.txt` | адреса разрешённых доменов |
| `report.md` | сводка: эталон канала, порог, таблицы |

## Интерпретация результатов

### Статусы пар

Одна проба — это пара «имя + адрес»:

| Статус | Значение |
| --- | --- |
| `PASS` | соединение установилось, сертификат получен |
| `DROP` | SYN не дошёл — похоже на фильтр по адресу |
| `RST` | соединение сброшено — похоже на DPI |
| `REFUSED` | активный отказ |
| `TLS_ERR` | TCP поднялся, TLS не ответил |
| `DNS_NX` | адрес неизвестен |

### Статусы HTTP-проверки

| Статус | Значение | Что делать |
| --- | --- | --- |
| ✅ `OK` | сервис ответил (2xx/3xx) | можно в список |
| ⚠️ `HTTP_ERR` | ответ 4xx/5xx | сервис работает, это не блокировка |
| 🤖 `BOT_BLOCK` | 403/429/503 | защита сайта от ботов |
| 🕐 `TIMEOUT` | нет ответа | повторить позже |
| 🌐 `DNS_ERR` | имя не резолвится | проверить DNS |
| 🎭 `SUSPECT_STUB` | страница-заглушка | оператор подменяет ответ |
| ↪️ `SUSPECT_REDIRECT` | редирект на оператора или блок-страницу | оператор подменяет ответ |
| 🛡️ `INTERCEPT_CERT` | сертификат не для домена, издатель неизвестен | оператор вклинился в соединение |
| 🧾 `SITE_CERT_MISMATCH` | публичный УЦ выдал сертификат на чужое имя | ошибка сайта |
| 🕳️ `SUSPECT_EMPTY` | 200 без тела | проверить вручную |

### Вердикты домена

| Вердикт | Условие |
| --- | --- |
| `разрешён` | каждый адрес проходит не реже порога и содержимое подтверждено |
| `частично` | проходит не каждый адрес домена |
| `содержимое не подтверждено` | адреса проходят, но сервис отдаёт не то |
| `не разрешён` | ни один адрес не прошёл ни разу |
| `нестабильно` | проходит реже порога — нужен ещё прогон |
| `не измеряется` | у домена не было адресов в наблюдениях |

Порог не фиксированный: он калибруется по эталонным доменам
(`configs/control-domains.txt`) в тех же прогонах, чтобы потери канала
не превращались в «заблокировано». Действующие значения печатаются в начале
и попадают в `report.md`.

## Инструменты

### check.py

Обычный запуск: канал → пары → HTTP-проверка → наблюдения → release.

```bash
python3 tools/check.py -o Megafon --phase on
```

| Флаг | По умолчанию | Описание |
| --- | --- | --- |
| `-o`, `--operator` | спросит | оператор; попадает в `runs/` и в release |
| `--phase off\|on` | unknown | выключен или включён режим белого списка |
| `--limit N` | все | первые N доменов (на обоих шагах) |
| `--repeat N` | 1 | повторов на каждую пару |
| `--timeout` | 3 | таймаут одной пробы пары, сек |
| `--http-timeout` | из конфига | таймаут HTTP-запроса, сек |
| `-c`, `--concurrency` | 6 | одновременных проб; выше 8 модем теряет соединения |
| `--chunk N` | 40 | доменов в блоке перед паузой (0 — без блоков) |
| `--chunk-pause N` | 60 | пауза между блоками, сек |
| `--pace N` | 0 | пауза между пробами, сек |
| `--interface` | маршрут по умолчанию | интерфейс для проб (модем) |
| `--dns` | системные | DNS-серверы для резолва |
| `--no-cache` | — | не брать адреса из `configs/dns-cache.json` |
| `--no-http` | — | без HTTP-проверки (быстрее, одно мнение) |
| `--http-limit N` | все | сколько доменов проверять по HTTP |
| `--http-concurrency N` | 10 | одновременных HTTP-проверок |
| `--no-release` | — | наблюдения записать, release не трогать |

### check_pairs.py

Только пары — для ручных экспериментов.

| Флаг | По умолчанию | Описание |
| --- | --- | --- |
| `-c`, `--concurrency` | 6 | одновременных TLS-проб |
| `--timeout` | 3 | таймаут пробы, сек |
| `--http-port` | 80 | HTTP-проба, если TLS не поднялся |
| `--family` | A AAAA | какие записи проверять |
| `--repeat N` | 1 | повторов на пару |
| `--dns-probe` | — | спросить DNS оператора по каждому домену |
| `--dns-cache` | — | адреса из кэша вместо живого DNS |
| `--dns-cache-extra` | — | локальный слой поверх общего кэша (можно несколько раз) |
| `--ipv6-check` | — | проверить IPv6 и отключить AAAA, если его нет |
| `--no-control` | — | выключить контрольные пробы (по умолчанию включены) |
| `--shuffle` | — | случайный порядок доменов |
| `--chunk` / `--chunk-pause` | — | блоки с паузами |
| `--interface` | — | привязать пробы к интерфейсу (Linux — имя, Windows — адаптер) |
| `--link-watch` | — | следить за живучестью канала во время прогона |
| `-o`, `--operator` | unknown | оператор для маркировки наблюдений |
| `--format` | both | `jsonl`, `tsv` или `both` |

Контрольные пробы определяют тип фильтрации: `ip` — разрешён адрес,
`sni` — разрешено имя, `pair` — только конкретная пара, `both_shared` —
ограничений не видно, `no_control` — контроль отключён.

### check-domains.py

Только HTTP-проверка.

| Флаг | По умолчанию | Описание |
| --- | --- | --- |
| `-c`, `--concurrency` | из конфига | одновременных запросов |
| `-e`, `--exclude` | — | исключить категорию доменов |
| `--dns-cache` | — | адреса из кэша |
| `--dns-cache-extra` | — | локальный слой поверх общего кэша |
| `--all-addresses` | — | проверять все адреса, а не до первого рабочего |
| `--no-verify-cert` | — | не сверять сертификат с доменом |
| `--no-stub-detect` | — | не искать страницы-заглушки |
| `--http-fallback` | из конфига | пробовать порт 80, если TLS не поднялся |
| `--operator NAME` | спросит | имя оператора для файла результата |
| `--limit N` | все | первые N доменов |

### classify.py

Вердикты по серии прогонов.

| Флаг | По умолчанию | Описание |
| --- | --- | --- |
| `-o`, `--operator` | — | оператор (обязателен) |
| `--phase` | on | какую фазу считать |
| `-d`, `--runs-dir` | `runs/<оператор>/<фаза>` | каталог наблюдений |
| `--min-ratio` | 0.8 | верхняя граница порога |
| `--control-file` | `configs/control-domains.txt` | эталонные домены |
| `--control-factor` | 0.75 | порог = доля эталона × коэффициент |
| `--min-attempts` | 2 | сколько попыток нужно для суждения |
| `--write-release` | — | записать списки в `release/` |

### build_common.py

Общий список по всем операторам.

| Флаг | По умолчанию | Описание |
| --- | --- | --- |
| `--phase` | on | фаза, из которой собирать |
| `--only` | все | учитывать только этих операторов |
| `--min-operators` | 1 | сколько операторов с данными нужно |
| `--write-release` | — | записать `release/whitelist-common.txt` |

### cache_dns.py

Кэш адресов в `configs/dns-cache.json`.

```bash
python3 tools/cache_dns.py --local --merge   # локальный слой, общий кэш не трогаем
python3 tools/cache_dns.py --merge           # обновить общий (его ведёт workflow)
```

Общий кэш обновляется workflow раз в неделю и при изменении `src/domains/`,
поэтому руками его лучше не переписывать: следующий `git pull` даст конфликт.
Свои адреса складывайте в локальный слой — `check.py` читает его поверх
общего и в git он не попадает.

### cell_watch.py

Журнал соты через `adb` (канал, уровень сигнала): помогает понять,
не менялась ли базовая станция во время прогона.

### win_check.py

Диагностика канала: показывает адаптеры, их тип (mobile/wifi/ethernet),
адреса и шлюзы, затем проверяет привязку — соединение через модем должно
быть, а через «чужой» адаптер падать.

```bash
python3 tools/win_check.py
```

Полезно, когда прогон предупреждает, что трафик идёт не через сеть
оператора, или чтобы убедиться, что привязка на Windows действительно
ограничивает маршрут.

### Вспомогательные

`merge_runs.py` — агрегация прогонов (устойчиво/флап), `pairs_report.py` —
отчёт по наблюдениям, `build_release.py` и `build_all_release.py` — ручная
сборка списков.

## Конфигурация

| Файл | Назначение |
| --- | --- |
| `configs/check-domains.json` | таймауты, заголовки, отпечатки curl_cffi, классификация ошибок |
| `configs/check_pairs.json` | параллельность и таймаут пар, порт, контрольные пробы |
| `configs/release.json` | операторы: название, источники, режим сборки |
| `configs/control-domains.txt` | эталон для калибровки порога |
| `configs/dns-cache.json` | адреса доменов, собранные вне сети оператора (обновляет workflow) |
| `configs/dns-cache.local.json` | ваш локальный слой поверх общего, в git не попадает |

Домены для проверки — в `src/domains/`, один файл на категорию. Формат:

```text
# Комментарий
yandex.ru
mail.ru
```

Строки-мусор и комментарии отбрасываются; домены нормализуются (регистр, порт, слэш).

## FAQ

**Нужен ли режим белого списка, чтобы пользоваться проектом?**
Нет. Инструмент измеряет то, что есть в вашей сети. Если режим включён,
получите список разрешённого; если выключен — увидите, как сеть работает
без ограничений (это полезная база для сравнения).

**Почему нельзя запускать с домашнего Wi-Fi?**
Вы измерите домашнюю сеть: там нет фильтрации оператора, и все домены
«пройдут». Инструмент проверяет канал и предупреждает.

**Почему часть доменов «частично доступна»?**
У домена несколько адресов, и оператор разрешил не все. Клиент выбирает
адрес сам, поэтому такой домен в итоговый список не попадает.

**Почему в `release/` меньше доменов, чем прошло проверку?**
В списки идут только домены с подтверждённым содержимым. Заглушки, парковки,
чужие сертификаты и «частично доступное» отбрасываются.

**Почему у операторов разные списки?**
Белые списки разные: у одного оператора домен разрешён, у другого нет.
Поэтому есть общий список (пересечение, безопасно везде) и списки
на оператора (шире, но применимы только в его сети).

**Домен проходит, хотя его нет в белом списке. Как так?**
Фильтр часто работает по адресу. Если домен живёт на общем хостинге или CDN,
его адрес может быть разрешён из-за соседнего сервиса. В отчётах такие домены
помечены как «на общем адресе»: они работают, но могут отвалиться при смене
адреса.

**Почему прогон идёт почти час?**
Темп ограничен специально: при высокой параллельности модем теряет
соединения, и разрешённые домены выглядят заблокированными. Прогон режется
на блоки с паузами — это условие достоверности, а не оптимизация.

**Можно ли ускорить?**
Уменьшить число доменов (`--limit`), отключить HTTP-шаг (`--no-http`)
или собирать базу только по нужным категориям.
